## 0. Why this amendment exists (and why it is NOT result-shopping)

The first formal batch under Amendment 1 (#2083, 2026-06-24, N=12/k=3, Opus)
returned a credible **NULL** (paired-median −1.67%, CI [−8.8%, +5.8%], Wilcoxon
p=0.33). **That NULL stays on record** — it is not overturned by this amendment.

That run surfaced a **corpus defect**: three fixtures got **0 DECIDED-success in
BOTH arms** (3/3 DECIDED-fail each):
`stable-api-build-add-export`, `config-backed-flag-rename-diff`,
`stable-api-codec-roundtrip`. A pair that fails in both arms is a **broken
instrument** — it measures nothing about the treatment (its paired delta is
≈0 noise), and it pollutes the success-conditional quality hold. The root cause
was fixture difficulty, not the treatment: over-strict, all-or-nothing gates over
8 chained tasks (and, for `build-add-export`, 8 async-control-flow modules) that a
competent cold agent cannot reliably complete in full.

**This is instrument repair, not p-hacking, and the distinction is load-bearing:**
- The repair targets fixtures that failed in BOTH arms (no signal), NOT fixtures
  that "didn't show the effect." Direction of the effect played no role in
  selecting what to fix.
- It is expected to LEAVE THE VERDICT UNCHANGED. The other nine pairs already
  produced the NULL; replacing three ≈0-delta pairs with working ones cannot
  manufacture a PROVEN. If the verdict were to flip to PROVEN off the back of
  this repair, that would itself be a red flag to investigate, not a win to claim.
- No statistical threshold changes (§2). No fixture is dropped; N stays 12.

## 1. What changed (the three repaired fixtures)

Each repaired chain keeps its `pairId`, `wasteReason`, stable file, M=8, and the
six anti-gaming constraints (Amendment 1 §2). Only the per-session tasks and the
gate were rewritten for **tractability**: simpler, independent, single-
responsibility tasks; gates that assert observable behavior and accept any
reasonable correct implementation (no exact-error-subclass, no incidental-format,
no timing traps). Each repaired chain was verified two ways before this commit:
(a) a naive reference solution passes Gate 0, the shipped initial tree fails it;
and (b) **a real cold-Opus calibration confirms DECIDED-success in both arms**
(the prior failure was unguided agents, so a reference solution alone is
insufficient proof):

| fixture | gate | cold-agent recheck (k=1) |
|---|---|---|
| `config-backed-flag-rename-diff` | `node --test test.mjs` | ok 1/1 both arms ✓ |
| `stable-api-codec-roundtrip` | `node --test test.mjs` | ok 1/1 both arms ✓ |
| `stable-api-build-add-export` | `node check-build.mjs` | ok 1/1 both arms ✓ (after dropping async-race tasks for simple API wrappers) |

The instructions remain de-leaked (no stable-symbol names) and treatment-neutral
(no read / don't-read coercion) — the coercive "read the file first" phrasing that
crept into one draft was removed.

## 2. What is UNCHANGED (frozen)

Everything statistical carries forward from the parent pre-registration and
Amendment 1, verbatim: hypothesis H1/H0; MDE ≥ 15% median cost reduction;
PROVEN/NULL/REFUTED rule; quality-hold 5pp; **N = 12**, **k = 3**, **M = 8**;
chain-total cost metric; Wilcoxon + bootstrap CI; single primary test at full M;
dose-response as a supporting readout only. Treatment = #890 recommendation as a
persistent `CLAUDE.md` (appended to any pre-existing convention file).

## 3. The corrected-corpus re-test

A new N=12/k=3 batch runs against the repaired corpus and reports its verdict by
the SAME §5 rule. It is labelled a **corrected-corpus re-test**: it supersedes the
2026-06-24 run *by instrument repair* (three broken pairs now measure something),
not by changing the analysis. Both runs are reported; the receipt links
2026-06-24 (NULL, 3 broken pairs) → corrected-corpus run.

Pre-existing caveat that this repair does NOT change: the effect is sub-MDE even
when the stable file is enlarged (the cross-session re-read is bounded by what the
tasks force the agent to read), so the corrected-corpus run is still expected to
be NULL — now a *clean* 12/12 NULL rather than 9-working + 3-broken.

## 4. Tooling note

applied before `--limit`) for cheap targeted re-calibration of specific fixtures.
No effect on a full run.
