## 1. Hypothesis

**H1 (primary, directional).** Injecting the #890 repo-map context-waste
recommendation into an agent's session context, versus withholding it, reduces
the token cost of completing a matched fixture task, with no degradation in task
success.

- Treatment increases the chance the agent references stable, high-centrality
  files instead of re-reading them, removing re-paid cache-read tokens that the
  #890 detector already prices as a `ReclaimClaim`
  (`src/lib/detectors/context/repo-map-context-waste.ts`,
  `cause: 'structural-prefix'`, `scaleTokens` on the cache-read prefix pool).
- This is a **Class A accounting effect with a Class B rider**
  (`v0.4-proof-engine.md` § Two claim classes): the token reduction is
  near-mechanical (bytes not re-read), so the experiment's job is mainly to
  confirm the Class B rider — that task quality holds while the tokens drop.

**Direction is pre-committed.** The primary test is one-sided (treatment reduces
cost). A cost *increase* under treatment is a refutation, not a win.

**Null hypothesis (H0).** The injected-vs-withheld cost distributions are
indistinguishable at the powered effect size: median paired cost delta is within
the minimum-detectable-effect band defined in § 5.

## 2. Treatment under test

The treatment is **the #890 repo-map context-waste recommendation, injected
vs withheld** — formally ratifying the front-runner that
`v0.4-proof-engine.md` (decision-record item 2) named provisional.

- **Detector:** `src/lib/detectors/context/repo-map-context-waste.ts` (#890,
  under epic #871 + #944). It names specific stable / high-centrality files and
  a few of their symbols, carries the measured reread-token estimate, and emits
  a priced `ReclaimClaim` against the cache-read pool.
- **Injection mechanism:** the binary `recs` shadow axis (#582) — Main =
  finding injected into `additionalContext`, Shadow = finding **withheld** —
  reusing the shadow-calls apparatus verbatim (ADR 0005 Tier 2;
  `axes.mjs` / `budget.mjs` / `judge.mjs` / `ledger.mjs` /
  `replay-runner.mjs` / `sandbox.mjs`). No parallel measurement stack.
  Note: `v0.4-proof-engine.md` supersedes ADR 0005 Tier 2 on two points used
  here — the corpus is a **fixture set** (not a replayed past task) and the
  verdict comes from **objective gates** (judge demoted to tiebreaker, not the
  primary scorer). The apparatus reuse above is unchanged; only the corpus and
  verdict source follow the newer proof-engine doc.
- **Eligibility screen (#583):** the fixture's waste pattern must be one #890
  actually fires on, the finding must not already be suppressed, and the finding
  text must pass the paraphrase-overlap screen against standing CLAUDE.md so a
  redundant finding's near-zero delta is not misread as "useless."
- **What is NOT the treatment.** The generic `workflow.redundant-reads` rule
  (flat, structure-blind) is not under test; #890 replaces it. Auto-apply of the
  fix is out (ADR 0005): injection only primes context; the agent acts or does
  not.

## 3. Corpus, design, and matched-pair N

*History prices, fixtures prove* (`v0.4-proof-engine.md` § The experiment).

- **Fixture set ref.** The curated fixture corpus + committed eval-result schema
  from the #975 shared substrate (the re-scope banner on #975 makes these
  critical path). The specific fixture-bundle commit/tag is recorded on the
  proof receipt's fixture-set ref; this pre-registration fixes the *selection
  rule*: only fixtures whose task exercises a stable / high-centrality file the
  #890 detector flags as re-read are eligible. Fixtures are frozen before the
  batch; none are added or dropped after the first run.
- **Design.** Matched pairs: the **same fixture task** run under control
  (finding withheld) and treatment (finding injected), in jailed reproducible
  worktrees. Pairing cancels between-task variance, the dominant noise source
  (`v0.4-proof-engine.md` § Design consequences).
- **Replication within pair.** Each arm runs **k = 3** times per fixture so
  within-pair variance is estimated, not assumed (k >= 2-3 per the spec). The
  per-fixture summary is the **median** of its k runs, per arm.
- **Pre-registered N.** Minimum **N = 12** matched pairs reach a DECIDED
  objective verdict (§ 4) before the analysis is read out. N is counted in
  *DECIDED pairs*, not attempted pairs: a pair where either arm fails an
  objective gate on all k runs is EXCLUDED from the effect estimate and reported
  separately as an exclusion (§ 6), never silently dropped. If fewer than 12
  pairs reach DECIDED, the batch ships as an engineering "not yet provable," not
  a null (§ 6).

## 4. Objective gates and metrics

The verdict comes from objective gates; the LLM judge is tiebreaker only
(#598). Per run, in order:

- **Gate 0 — success gate (binary, per run).** The run is DECIDED-success only
  if it passes the fixture's objective acceptance: **build passes, the fixture's
  committed tests pass, and the diff satisfies the fixture's acceptance check.**
  A run failing any of these is DECIDED-fail. A run that cannot be classified
  (worker crash, infra error, timeout) is UNRESOLVED and contributes only to the
  exclusion accounting.
- **Primary metric — cost delta.** Total task cost in tokens, converted to
  dollars by the v0.3 efficiency accounting (the ruler). Reported as the
  **paired median delta** (treatment − control) with a bootstrap 95% confidence
  interval. Because variance is heavy-tailed, the test is the **Wilcoxon
  signed-rank test** on paired per-fixture medians — never raw means.
- **Secondary metric — latency delta.** Wall-clock to DECIDED-success, same
  paired-median + bootstrap-CI treatment. Reported, not gated: a latency
  regression is disclosed but does not by itself refute H1.
- **Quality hold (the Class B rider).** Treatment must not lower the
  DECIDED-success rate. Pre-registered as a non-inferiority check: treatment's
  success rate is within a 5-percentage-point margin of control's. A larger
  success drop converts a cost win into a refutation.
- **Judge — tiebreaker only (#598).** The existing task-agnostic 6-dimension
  `judge.mjs` rubric is consulted ONLY to break a tie when the objective cost
  result lands inside the MDE band (§ 5) AND the quality hold passes. It can
  never override an objective gate and never manufactures a verdict on its own.

## 5. Decision rule (quantitative — threshold + N)

Read out only after the pre-registered N (§ 3) of DECIDED pairs is reached.
All thresholds are fixed here:

- **Minimum detectable effect (MDE).** The batch is powered to detect a
  **>= 15% median reduction in per-task cost** (treatment vs control). Effects
  with absolute magnitude below this band are, by pre-registration,
  "indistinguishable from null" — a scientific null, not a shrug.
- **PROVEN (positive receipt).** ALL of:
  1. paired-median cost reduction **>= 15%**, AND
  2. the bootstrap 95% CI on the paired-median cost delta lies **entirely below
     zero** (excludes no-effect), AND
  3. Wilcoxon signed-rank **p < 0.05** one-sided, AND
  4. the quality-hold non-inferiority check (§ 4) passes, AND
  5. **N >= 12** DECIDED pairs.
- **NULL (null receipt, § 6).** N >= 12 DECIDED pairs reached AND PROVEN is not
  met — either the effect is below the 15% MDE, or the CI straddles zero, or the
  signed-rank test is non-significant. Ships with the same rigor as a positive
  receipt.
- **REFUTED.** The paired-median cost delta is positive (treatment costs more)
  with CI excluding zero, OR the quality-hold check fails. Reported honestly;
  refutation is still an answer to the leading question.
- **Tiebreaker scope.** The judge (§ 4) is consulted only when the cost result
  is inside the MDE band and quality holds — i.e. only to nudge a NULL toward a
  qualitative read, never to upgrade a NULL to PROVEN.

No metric, threshold, N, or test named above may change once the batch has run.

## 6. Null-branch and failure criteria (what counts as a credible null)

Per the bust taxonomy in `v0.4-proof-engine.md`:

- **Credible scientific null.** A null is credible — and ships as a null
  receipt — ONLY when the batch actually ran to the pre-registered N >= 12
  DECIDED pairs and the decision rule (§ 5) returned NULL. A credible null
  states the observed paired-median effect, its CI, the achieved N, and that the
  effect fell within / the CI straddled the powered MDE band. It is a real
  artifact and a real answer.
- **NOT a null — engineering "not yet provable."** Fewer than 12 DECIDED pairs,
  the fixture corpus or injection harness could not run, or excessive
  UNRESOLVED runs prevented reaching N. Reported explicitly as "not yet
  provable," never dressed up as a null. The milestone may not end in a shrug.
- **Exclusion accounting (no silent drops).** Every excluded pair (an arm
  failing all k runs) and every UNRESOLVED run is counted and reported alongside
  the DECIDED-pair effect. A high exclusion rate is itself a disclosed result.

## 7. Receipt linkage and reproducibility

- This document's commit becomes the **`preRegistrationRef`** on the proof
  receipt (the receipt schema is a separate epic-#995 child; this pre-registers
  what that receipt must carry, it does not define the schema).
- The receipt records, against the fields fixed here: experiment ref +
  `preRegistrationRef`; observed waste pattern + the #890 detector ref +
  $X/mo from real history; fixture-set ref + design (matched pairs, k=3,
  injected vs withheld) + DECIDED N; effect size + bootstrap CI + per-dimension
  deltas; verdict (PROVEN / NULL / REFUTED) by the § 5 rule; projected $Y/mo
  reclaim labeled an extrapolation; the team-legible rollout prescription; and
  the external-review ref.
- **Model-version scope.** Every result above is conditional on the model
  version the batch ran against. The receipt names that version and carries a
  freshness state; this pre-registration's thresholds do not change on
  revalidation — a revalidation run re-applies the SAME § 5 rule on the SAME
  fixtures against the new model.
- **Reproducibility.** A skeptic can re-run the frozen fixture bundle through
  the same jailed-worktree apparatus and the same § 5 decision rule and reach
  the same verdict class, modulo model-version drift (which the freshness state
  discloses).
