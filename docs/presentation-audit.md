# Presentation Audit (Issue #321)

## Goal

For every data-presentation **surface** in the dashboard, decide whether its current
visual form is the most effective way to show that surface's underlying data. Each
verdict is one of **keep / tweak / replace**, argued from the surface's real data
shape (the component file + its `src/lib/parse-*.ts` parser), not from the chart's
name.

## Audit heuristics

- Part-to-whole summing to 100% → pie/donut; otherwise **not** a pie.
- Ranking/comparison of magnitudes → sorted bars; the sort key **must** equal the bar length.
- A rate (errors/calls) needs its denominator visible (count label, or 2-D rate-vs-volume).
- Distribution → histogram/box, not a bar-per-item.
- Time series → line/area, not categorical bars.
- Long lists → ranking + search + virtualization/pagination + a sane default sort beats unbounded scroll.

**Worked exemplar — `ErrorRetry.tsx:239-281` "Top Tools by Error Rate":** a horizontal
bar of `errorRatePct` sorted by error **count**. Bug family: form/metric mismatch (a rate
is not part-to-whole), sort ≠ encoding (sorted by count, bars show rate), hidden
denominator (100% on 1 call looks identical to 40% on 500). See its row below.
