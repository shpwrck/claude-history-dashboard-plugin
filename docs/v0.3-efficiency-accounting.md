## 1. The reframe: the North Star is a compass, not a gate

On the maintainer's own `~/.claude` (one-time private pull as of 2026-06-08, 31-day
window, repriced at API rates — not reproducible; see the provenance note above):

- **Shadow API bill ≈ $9,447/mo = ~47× the $200 Max-20x price** (94× vs Max-5x).
- To literally satisfy `optimized_API < Max` you must cut **~98% of spend**. No set of
  recommendations does that. **The literal North Star inequality is unwinnable as a gate.**

So #724 is re-read as a **compass for ruthless efficiency**: success is the **reclaim
trendline** — how much waste the engine can attribute and you can cut over time — not
crossing a line. The honest realistic floor under aggressive efficiency is **~$4–5k/mo
(≈20–25× Max)**, hard floor **~$3.5–4k (≈18–20×)**: a heavy Opus dev workload is largely
irreducible. "Stay on Max" remains the correct verdict essentially forever; that is a
feature of honesty, not a failure.

## 2. Where the dollars actually are

Two orthogonal lenses on the same $9,447:

**By token type — *where* the money sits (the cache dominates):**

| pool | $/mo | share |
|---|---|---|
| cache-read | $5,449 | 58% |
| cache-write | $2,466 | 26% |
| output | $1,327 | 14% |
| input | $205 | 2% |

→ **84% of the bill is context (cache read+write)** re-fed every turn. Also: **94% Opus**,
**88% `sdk-cli`** (headless/agent runs). You pay to *re-read context*, not to *think*.

**By category — *why* the money was spent (what the engine can act on):** today the engine
attaches `estSavingsUsd` in **exactly one of six** detector categories — `cost` 8/9 files;
**`context` 0/7, `workflow` 0/19, `reliability` 0/11, `safety` 0/4, `activity` 0/2**. The
signals already fire (`detectors/context/low-cache-hit.ts` computes `hitRate`;
`detectors/workflow/runaway-workflow-cost.ts` carries `totalTokens`+`agentCount`) — they
just carry no dollars. `recommendations.ts:130` `totalEstimatedSavings` is a blind `.reduce`
with no denominator, no per-category rollup, no dedup.

**Coverage gauge (hypothesis, as of 2026-06-08): the engine has a dollar opinion on only
~35% of the bill** and is structurally blind to the 84% that is context. The ~35% was
estimated from the unpreserved pull and cannot be independently re-derived (see the
provenance note). *That gap is the whole problem.*

## 3. The lever roadmap (deduped, by hypothesized $/mo)

These are **orthogonal pools, not additive** — naive summing quadruple-counts the one
$5,449 cache-read pool seen through five parsers. All $/mo ranges in this section are
order-of-magnitude **hypotheses** derived from the unpreserved 2026-06-08 pull (see the
provenance note), not verified estimates.

**Structural (cost/context) — the big money:**

1. **Model-price on *cached* tokens** ($2.5–4k) — Opus→Sonnet on the safe headless fleet
   reprices cache-read/write/output on the *same* tokens (Opus cacheRead $0.50/M vs Haiku
   $0.10/M). Half-built (`entryCostAtModel`, `CHEAPEST_MODEL`).
2. **Fixed-prefix diet** ($1.5–3k) — CLAUDE.md/AGENTS.md (~1,400 lines) + MEMORY index +
   skills/tool reminder + **duplicate `github`/`githubmcp` MCP servers (~80 schemas)** are
   re-billed as cache-read every turn × every session. Dedupe the two GitHub servers = free win.
3. **Turn-count / compaction discipline** ($1.5–2.5k) — a 400-turn session pays the prefix 400×.
4. **Batch API −50%** ($2–4k) — the lever all enumerators initially missed. `sdk-cli`
   automation (burn-epic, replay, workflows) is non-latency-sensitive by construction. Flat
   half-off the batchable subset, **stacks multiplicatively** with 1–3. *(Maintainer: most
   automation tolerates <24h turnaround → in scope.)*
5. **Fan-out timing tax** ($1.2–2.5k) — concurrent agents all pay cache-*write* (1.25–2×),
   none get the 0.1× *read*, because the cache isn't readable until the first response
   streams. Warm one, then fan the rest.

**Cause-side (the "other sections" — real but modest, reliability-dominated):**
**~$450–900/mo NEW** honestly dollarizable on top of the above:

| lever | category | $/mo | dollarizable |
|---|---|---|---|
| retry-prefix-rewaste (failed tool → retried turn re-pays prefix) | reliability | $300–450 | yes (gate on `RetryGroup.hasErrors`, *not* count) |
| redundant-reads | workflow | $70–110 | yes (direct-estimate only) |
| overload-reretry (529/429, `retryAttempt>1`) | reliability | $40–80 | yes |
| native-tool-bypass | workflow | $40–70 | yes |
| re-derivation (cross-session re-explore) | workflow | $50–200 | **deferred** — needs session→cwd join |

**Flag-only ($0 — honest, avoids the #726 unfalsifiable trap):**
- **safety / deceit-redo** — no model-deceit detector exists yet (`safety/` has only
  allow/deny/dangerous-bypass/prompt-friction); a 2,780-transcript pre-scan found **0 clean
  instances**. Needs the #683 judge.
- **prompt hygiene (#504)** — ~$400–900/mo *advisory ceiling* (real money!) but
  "a better prompt would've saved N turns" is unfalsifiable.
- **stop-hooks (#710)** — `durationMs` present on ~7% of fires → latency dollars would be fabricated.

The reliability gross of **$2,065 (22% of bill) in error-affected sessions is mostly
legitimate co-located work** — only the re-paid residual is waste. Do not book it whole.

## 4. The accounting model — "guarded-marginal"

Chosen over token-partition, pool-cap, and Shapley because it is the only model that is an
**optional-field add** (the rivals need a per-token ledger no parser produces) and is
**overflow-proof by construction**.

**Sequential-residual cascade.** Price a per-`(scopeKey, pool)` residual matrix via
`entryCostAtModel`. Apply each lever's counterfactual to the running residual in `orderKey`
order; book `marginal = max(0, billBefore − billAfter)`. Then:

```
sum(marginal) ≡ billOriginal − billFinal      // overflow is structurally impossible
```

The four levers reaching the $5,449 cache-read each act on a *smaller residual* than the
last, so their slices are disjoint. Guardrails lifted from the rival models: a **global
`residual ≥ 0` invariant** (reject+log, never silently clamp) and a **canonical `scopeKey`
precondition** (reject claims that don't resolve to a real priced entry-group).

**Batch** is not a lever in the order — it's a terminal −50% multiplier on the *surviving*
post-counterfactual cost of the batchable subset, so it never discounts a deleted dollar.

### The contract (generalizes #858) — with the cause/category extension

```ts
type PoolId = 'cacheRead'|'cacheWrite5m'|'cacheWrite1h'|'output'|'input';

interface ReclaimClaim {
  leverId: string;            // OPENED (was a closed 6-union). Convention `${category}.${slug}`
  category: RecCategory;      // reuse the EXISTING enum in detectors/types.ts — do not mint a parallel one
  cause: CauseKey;            // finite taxonomy: structural-prefix | model-tier | failed-tool-retry | ...
  orderKey: number;           // causes [10,40) ahead of structural cost/context [40,90)
  ownedPools: PoolId[];
  scopeKey: string;           // canonical `${sessionId}|${model}` (re-derivation uses `${cwd}|${model}`)
  scopeFilter?: 'all'|'batchable'|'fanout-only'|'retried-turns'|'redo-turns'|'cross-session-first';
  counterfactual:
    | { kind:'reprice'; fromModel:string; toModel:string }       // swap / batch
    | { kind:'scaleTokens'; poolDeltaFrac: Partial<Record<PoolId,number>> } // delete a pool fraction
    | { kind:'convertRate'; rateFrom:PoolId; rateTo:PoolId }      // fanout write→read
    | { kind:'flag-only' };                                       // books $0, mutates no residual, evidence only
  evidenceTokens: number;     // feeds per-category coverage only; flag-only evidence never enters the dollar identity
}
// Recommendation.estSavingsUsd becomes a DERIVED back-fill of the booked marginal (legacy callers keep working).
```

`category` + `cause` are **pure labels** — they change grouping/reporting, never the
arithmetic — so the identity and `residual ≥ 0` hold under any ordering. The rollup produces
both a **per-lever** and a **per-category** marginal breakdown (so the trendline can say
"reliability = $X reclaimable") and **per-category coverage** (a mostly-flag-only category
honestly shows low dollar coverage rather than a padded figure).

### Ordering policy: **cause-first** (decided)

The cascade identity is order-invariant, so order is a pure *attribution-policy* choice,
decided on **decision-usefulness**: a retried-turn prefix re-read is *both* reliability
waste *and* prefix bloat over the same cache-read. If structure ran first it would swallow
those tokens and the trendline would falsely read "fixing flaky tools saves $0." Cause-first
makes each marginal equal the counterfactual the user can independently act on. Intra-cause:
deterministic-before-judge (reliability → safety-redo → workflow → activity).

### Coverage gauge & trendline (plotted separately, never multiplied)

- **Coverage** = `price(claimed tokens) / repriced totalBill`. The denominator is the
  repriced actual bill; `[1m]` already prices correctly at base Opus rates (see §6), so the
  only denominator-quality work is the dedup key (#946) — without it the same pool seen
  through multiple parsers is double-counted. Reads "the engine has a dollar opinion on X%
  of your real bill"; unclaimed pools *lower* coverage.
  Target v0.4: ~35% → 80–85% (earned as context detectors get dollar contracts, not asserted).
- **Reclaim trendline** = per ISO-week, plot `baseline(p)` = repriced **actual** bill and
  `baseline(p) − reclaim(p)`. The gap is the reclaim; its **slope** is the compass needle.
  Because `baseline` is the actual bill (not a frozen snapshot), there's nothing to game, and
  as fixes land `claudeMdMarksApplied` suppresses detectors → the predicted line converges up
  to realized spend. **That convergence is the realized-vs-predicted calibration gate (#726).**
